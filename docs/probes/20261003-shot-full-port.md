# Shot 完整移植短期记忆（2026-10-03）

Core spec 049。NARust-o 本地提交 `cd685cd` 的 `examples/_games/shot/` 有 `mod.rs`、`ai_trait.rs`、`ai_null.rs`、`ai_nar.rs`、`ai_nar2.rs`；Cargo 许可 `MIT OR Apache-2.0`。用户授权借鉴。Web Demo 现由 `src/shot-lab-model.ts` 与 `src/shot-lab.ts` 承载六种入口；OpenNARS Worker 是独立的 NARS 适配，不复制原作的 NARS 内存。

## 原作已确认的世界规则

- 50×20 整数格世界。方向 `Up/Down/Left/Right`，顺/逆时针旋转与方向向量明确；玩家有名称、位置、速度、方向、射击状态、命中/漏射、距上次命中步数与平均命中间隔。
- 各步顺序：形成所有玩家位置的共享感知 → 每名 AI 根据 NARS 操作行动 → 绘制 → 处理射击与成功/失败反馈 → 移动玩家（边界停止、阻止同格重叠）→ 各 AI 推理周期 → 进化附加逻辑。
- 射击沿朝向同一行/列立即判断目标，被击者重生，射手统计命中或漏射；原文用同步 `sleep` 做命中停顿，浏览器不能照搬阻塞，应以不影响世界/推理时钟的动画表达。
- `shot_test`、`shot_test2` 为静态靶单 NARS，区别是绝对上下左右 vs 相对转向/前进；`shot_test_2p`、`shot_test_2p_2ai` 为双 NARS；`shot_test_evolve`、`shot_test_evolve2` 会按命中率/命中间隔排名，复制领先者、淘汰落后者并重生。最后模式起始含两种 AI，人数上限更高。
- `AiNar` 目标跟踪、差分感知、无位移时重报状态、防止环境边缘冻结、移动/射击反馈和动态推理周期，是玩法特征而非 UI 杂项；`AiNar2` 改用身体相对方向感知与 `left/right/forward/shot` 操作。

## 2026-10-04 已落地的进化合同

- 世界模型保留原作的适应性分数：`round(hitRatio / (tick - lastHitTick + 1) * 10000)`；只对已有射击记录的 NARS 玩家排名，分数越大越优。
- 排名按分数升序保存；最后一项是克隆来源，第一项是在超过半数参与排名时被淘汰的落后者。玩家数小于上限时复制 2 个，等于上限时复制 1 个，超过上限时不再复制。
- 克隆保留来源玩家的命中、漏射、命中间隔、方向与 AI 类型；随后所有存活玩家统一随机重生。被射击目标也按原作随机位置与方向重生，而不改变射手统计。
- `stepShotWorld()` 返回结构化 `rankings`，同时写入 `EVOLVE:RANK`、`EVOLVE:CLONE`、`EVOLVE:EVICT` 事件，页面日志可追溯进化依据。
- 纯模型合同覆盖四舍五入排名、克隆统计继承、命中重生、移动阻挡和 500 刻进化；尚未据此宣称所有原作 AI 的长期行为已经等价。
